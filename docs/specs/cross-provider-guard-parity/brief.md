# Brief: Cross-Provider Guard Parity

> Generated by `/team-brief` — 2026-06-19 · revised 2026-06-19 after 3 independent reviews (architecture, security, codex cross-model)

## Context

NanoClaw runs three interchangeable agent providers — **Claude** (Agent SDK), **Codex** (`codex` runner), **OpenCode** (plugin runtime). Standing principle: these are **one team that must behave identically** — same command guards, same tool access, same tool calls, same container/workgroup behavior — and that sameness must hold **by construction** for providers added later. Infrastructure may differ; agent behavior must not.

Root cause of the divergence: **`claude.ts` is the "fat" policy owner.** Several bash-command guards are defined *inline* there. Codex inherits them by *importing* `claude.ts`; OpenCode imports nothing from it, so OpenCode is **blind**. Steps 1–3 (shipped) proved the fix pattern for the git-clone guard: lift policy into the shared core (`block-destructive-core.ts`), have every adapter consume it, pin it with `conformance.test.ts`.

**Review follow-up already shipped (bootstrap `d23df80`, nanoclaw `f7fa1740`):** the 3 reviews found the shipped git-clone guard was weaker than first claimed. Safe corrections landed: `workgroup` added to the managed-dir regex; verdict narrowed to `{allow|block}` so adapters can't fail-open; OpenCode + Claude fail-closed on any non-`allow`/thrown evaluator; the overclaiming comments rewritten as honest **advisory** framing; `container/CLAUDE.md` wording de-contradicted. This brief covers the remaining, design-level work.

**Framing correction the reviews forced (carry into design):** the git-clone guard is an **advisory workflow nudge, not a containment boundary** — the agent already has RW to managed dirs, so bypasses (bare `git clone <url>` into cwd, `git -C`, renamed binary, symlink) are not privilege escalation. Do not over-claim. Making it airtight (cwd+relative-target resolution) is explicitly **out of scope**.

## Requirements

- **Guard policy is single-source in the shared core**, consumed by thin adapters. OpenCode gains the guards it lacks today: **self-approval**, **snowflake-connector**, and **email-gate** (alongside the already-shared destructive, file-protection, git-clone).
- **self-approval & snowflake-connector** are refactored from inline `HookCallback`s (returning `denyBash`) into **pure `(cmd) => verdict` evaluators** in the core (named, e.g., `evaluateSelfApproval`, `evaluateSnowflakeConnector`), vendored, pinned by conformance, with `claude.ts` reduced to a thin verdict→`denyBash` adapter (fail-closed fallback retained).
- **email-gate** is refactored to a **pure `evaluateEmailSend(command, env) => verdict|null`** (env passed as an **injected snapshot** — `NANOCLAW_IS_SCHEDULED_TASK`, `GOOGLE_WORKSPACE_CLI_CREDENTIALS_FILE` — never read from `process.env` inside the core). The approval flow is delivered by each adapter reusing **the session-DB gate primitive it already owns**: Claude/Codex keep the **async** `awaitDeliveryAck` path (C3 — untouched); OpenCode uses the **synchronous** `runNanoclawGate`/`writeGateRequest`+`pollDeliveredTable` it already uses for the destructive gate (its `tool.execute.before` is a sync throw). NOT a bespoke injected-callback interface.
- **OpenCode MCP tool-denylist parity** (its own design item, NOT folded into the verdict-conformance suite — it's a flat string list, not a verdict): OpenCode must enforce the disallowed-tools set Claude enforces via `disallowedTools`+`preToolUseHook` and Codex via the imported hook. Must (a) map Claude-SDK tool names to OpenCode tool names (some builtins like `CronCreate`/`ExitPlanMode` may not exist there), and (b) run around OpenCode's **`permission` auto-reply `'always'`** path (`opencode.ts`), not only `tool.execute.before`.
- **OpenCode fails CLOSED when the guard plugin is absent.** Today `opencode.ts` logs a warning and keeps `permission:'allow'` with the plugin omitted → an unguarded agent. The feature must make a missing guard plugin a hard failure (refuse to spawn, or deny-by-default).
- **Env/secret parity (`sanitize-bash`):** OpenCode shell tools must NOT see the auth env vars Claude/Codex strip via `sanitize-bash`. (sanitize-bash is a command-*transform*, not a verdict — so it's out of *verdict* conformance — but its secret-stripping **effect** is a required parity outcome, achieved however design prefers: a transform port, env scrubbing at spawn, or excluding those vars from the OpenCode child env.)
- **Clone destination → `/workspace/workgroup/repos/<name>` (shared)**, per `docs/specs/workgroup-shared-fs.md` (repos are shared across siblings). Fall back to `/workspace/agent/repos/<name>` when no workgroup is mounted; keep resolving the legacy `/workspace/agent/<name>`. Includes the spec's path-allowlist repoints (`poll-loop.ts`, `mcp-tools/core.ts`) so the shared repo root is reachable.
- **`clone_repo` must not reuse the wrong repo:** idempotency currently keys on *name*; verify the existing clone's `origin` matches the requested URL before returning it, and don't silently `rm` a non-git dir.
- **Conformance seam = core-conformance + per-adapter WIRING tests + per-adapter DISPATCH-COVERAGE tests.** Wiring tests prove a verdict maps faithfully; dispatch-coverage tests prove the adapter's **real entrypoint is actually invoked** for the relevant tool classes (e.g. `NanoclawGuard()['tool.execute.before']` with `{tool:'bash'}`, `{tool:'edit'}`, a denylisted tool; the generated Codex hook CLI) — the "reached, not just correct" gap that caused the original divergence. Plus a **guard-absence-fails-closed** assertion.
- **`/clone-as-*` parity contract:** `/clone-as-codex`, `/clone-as-opencode`, and a template for a future `/clone-as-<provider>` document that a new provider's adapter MUST route through the shared core, fail closed if the guard is absent, and pass the conformance + dispatch-coverage tests before it's "done."
- **`mnemon-real`:** migrate to a pure core evaluator if cheap (it's a verdict, gated on `MNEMON_READ_ONLY`); don't let it expand scope (defense-in-depth only).

## Constraints

- [HARD] Single-source policy: no adapter carries its own copy of a migrated guard's policy, except explicitly-marked fail-closed fallbacks used only when the core can't load.
- [HARD] `block-destructive-core.ts` (workflow/ tree) is source of truth; the `workflow-agents/` copy is vendored via `scripts/vendor-guards.mjs` (`--check` gate). **New core *files* are NOT vendored unless added to `VENDORED_FILES` (`vendor-guards.mjs:33`)** — design must either extend the existing core file (no script change) or add new files to that list (and the `--check`).
- [HARD] email-gate's existing human-approval flow for Claude/Codex is preserved exactly (no regression); the core stays I/O-free (env injected, gate primitive supplied by the adapter).
- [HARD] Fail-closed on security guards everywhere, including when the guard plugin/core is absent (this now includes the OpenCode plugin-absent case).
- [HARD] Spans `nanoclaw-v2/container/agent-runner` + `davekim917/bootstrap/plugins/workflow`. Bump bootstrap `workflow` `plugin.json` + `marketplace.json` and `workflow-agents` `.codex-plugin/plugin.json` per convention.
- [HARD] `codex exec` sub-delegation fires no hooks — instruction-only on that path; do not claim hook-parity there.
- [HARD] The git-clone guard is **advisory**; airtight bare-clone/`git -C`/symlink closure is out of scope. Comments/docs must say so.
- [SOFT] Use core-conformance + per-adapter wiring/dispatch tests, not a cross-repo real-invocation harness.
- [SOFT] Keep `claude.ts` edits minimal-risk (hot path); migrate guards incrementally with tests green at each step.

## Non-Goals (Explicitly Out of Scope)

- Making the git-clone guard airtight against cwd-relative / `git -C` / renamed-binary / symlink bypasses (it's advisory).
- A cross-repo real-adapter-invocation conformance harness.
- Adding any **new** guard policy — this is parity of **existing** policies.
- Migrating existing scattered group-root clones into `repos/` (separate "step 4").
- Host-side provisioning beyond the clone-destination repoints (mounts, scoped creds) — already provider-agnostic.

## Key Concepts

- **Shared guard core / thin adapter / vendor-guards / conformance contract** — as before.
- **Dispatch-coverage test:** drives an adapter's *real* entrypoint to prove the guard is *reached* for a tool class (vs. a wiring test that proves a fed verdict maps correctly).
- **Gate primitive (per adapter):** the session-DB approval mechanism each runtime already owns — Claude/Codex async `awaitDeliveryAck`; OpenCode sync `runNanoclawGate`/`writeGateRequest`+`pollDeliveredTable`.
- **Injected env snapshot:** env values the email-gate evaluator needs, passed in so the core stays pure/deterministic.
- **Advisory guard:** a workflow nudge, not a containment boundary (the agent already has the access).

## Open Questions (defaulting unless flagged)

- **VENDORED_FILES vs extend-existing-core:** defaulting to extending `block-destructive-core.ts` (zero script change) unless a guard clearly warrants its own file. Flag if you want separate files (then `vendor-guards.mjs` + `--check` must be updated).
- **tool-name mapping (Claude→OpenCode):** defaulting to design enumerating the real OpenCode tool names; the denylist is effective only for names that exist there.

## Success Criteria

- `conformance.test.ts` pins core evaluators for self-approval, snowflake-connector, email-gate (named exports), plus existing.
- Per-adapter **wiring** tests (verdict→abort mapping) AND **dispatch-coverage** tests (real entrypoint reached for bash/edit/denylisted-tool) pass for Claude, OpenCode, Codex.
- A test asserts each adapter **fails closed when the guard core/plugin is absent** (OpenCode especially).
- OpenCode blocks/gates self-approval, snowflake-connector, and email-send at parity (tests + smoke in a respawned OpenCode container); OpenCode rejects a disallowed tool; OpenCode shell cannot read the auth env vars Claude/Codex strip.
- `clone_repo` lands repos in `/workspace/workgroup/repos` (fallback `/workspace/agent/repos`), reuses an existing clone only when `origin` matches, and never silently deletes a non-git dir.
- `claude.ts` carries no migrated-guard policy except marked fail-closed fallbacks; Codex inherits unchanged (tests green); email approval flow unchanged for Claude/Codex.
- `vendor-guards.mjs --check` passes (new files added to `VENDORED_FILES` if any); bootstrap plugin versions bumped.
- `/clone-as-*` document the parity contract (route through core + fail-closed + pass conformance/dispatch tests) as a completion gate for new providers.
- Full guard suite + container typecheck + provider suite green across both repos.
