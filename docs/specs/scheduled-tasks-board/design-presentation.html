The incident that demanded this

Seventeen schedules died in silence. Nothing noticed for two weeks.

May 27 – 31, 2026

A reply-routing bug stamped task output onto sibling tasks' future fire rows. The idempotency guard read those phantom replies as "already answered" and suppressed every interleaved daily series — briefings, email recaps, parental monitoring, wiki maintenance. No failed status was ever written. The rows sat pending, looking perfectly normal to anything that reads status.

The fix shipped June 10. The lesson shipped here: a dead schedule must be impossible to miss, and death must be detected by arithmetic, never by status.

Design principles it forced

Truth on read. No materialized copies of scheduling state — every prior incident was derived-state drift.
Derived health. Stalled = now − next_fire beyond grace. Status is never the signal.
Unhealthy first. A die-off is the first thing on screen, never row 28.
Fail closed, fail loud. Every mutation path's worst case is visible, never silent.

Architecture · zero new state

Reads sweep the truth.
Writes go through one door.

Read path

One session per event-loop tick — the host's delivery polls and SSE never stall. Warm cache serves in microseconds; a board mutation invalidates it synchronously so you always read your own write.

Why no index table

Both prior incidents were derived state diverging from truth. A materialized copy of schedules is the same trap with a nicer name. The board reads the rows that actually fire.

Proven primitives

Every verb maps to a primitive already in production — updateTask, pauseTask, cancelTask, scheduleTask. One additive change: moves carry pre-task scripts.

Health model · arithmetic, not status

A dead series cannot hide.

The May die-off left zero failed rows — every victim looked "pending". So health is computed, and the three ways a series can die silently each have a dedicated detector.

Detector 1 — Overdue arithmetic

stalled ⇐ now − process_after >
  max(cron_interval × 0.5, 2 × sweep)

Catches the poison-class death: a live row past its slot with no terminal status. Exactly the June signature — verified against the real incident data as the acceptance test.

Detector 2 — Residual strand

A terminal row still carrying its cron, persisting across sweeps, means the scheduler is failing to mint the successor — the swallowed cron-parse-error path found during review. Flagged stalled.

Detector 3 — Duplicate successor

Two live rows in one series can double-fire while one hides behind the latest-row read shape. A GROUP BY counter surfaces both rows, flagged unhealthy.

The marquee verb · cross-agent moves

Hand a schedule to your Codex sibling.
With the credential delta on the table.

1
Preview — gated at mutation tier
Wiring validated dry-run; destination channel_type translated to the sibling's variant (same channel, its own bot).
2
Credential delta confirm
OneCLI secret names the task gains and loses — values never leave the gateway. Cross-workgroup moves name the boundary crossing.
3
Execute re-validates everything
Authz, scope, wiring, and delta re-checked server-side; a changed delta returns 409 delta_changed and forces re-confirm.
4
Cancel source, insert target
Cancel-first: the bad day is a brief gap, never a double-fire. Prompt, pre-task script, cron, and overrides travel atomically.
!
Compensation that cannot vanish a series
Insert fails → source restored from snapshot. Both fail → durable repair record, surfaced as stalled on the strip. A successfully-placed target is never deleted.
5
Invariant check + audit
Exactly one live row fleet-wide per series — verified after every move, alert on violation.

Security · this is remote control of unattended execution

Strictest tier by default.

Per-verb gates

Every mutation — and move-preview, which reads vault secret names — requires owner or global-admin. Scoped admins are read-only within their groups. The auth cookie alone never authorizes a write.

Scope-filtered reads

"Fleet-wide" means the groups you're authorized for — disclose-as-not-found, same contract as every existing dashboard API. SSE frames carry the owning group and filter per connection.

Audit without leakage

Every change recorded: who, when, what. Bodies stored as sha-256 + 512-char preview — scripts hash-only, never verbatim. 90-day prune. No second plaintext copy of unattended code.

Scope · v1 ships the pain-killer

In, out, and two honest amendments.

In — v1

  • Fleet-wide visibility: groups, channels, cron, next fire (UTC + local), prompts, scripts, overrides
  • Derived health + the three silent-death detectors, unhealthy-first
  • Edit · pause/resume · run-now · cancel · move with credential-delta confirm
  • Module-owned badges with accurate reseed warnings; thread-loop badges
  • Hashed audit trail · owner/global-admin gates · one new session-DB index

Out — deliberately

  • Create-from-board — creation stays in chat where it works today
  • Proactive alerting — visibility first; tripwires exist separately
  • Central-table storage migration — recorded wart, separate decision
  • Moving thread-bound loops — their lifecycle is the thread, by design
  • Mobile drawer editing — read-only on small screens, v1
⚠ Two brief amendments need your sign-off
1 · Provenance table. The brief assumed stamping audit data into row content — review proved no primitive can write it. The minimal viable alternative is one hashed-body table with a 90-day prune. Same intent, honest mechanism.
2 · Skipped-vs-quiet fires. Distinguishing script-gated skips from quiet runs needs a fire-outcome record the firing path doesn't write — touching it violates the no-firing-changes constraint. v1 merges them under "completed (no chat output)"; v2 owns the real record.
