# PR #961 — prune dangling workgroup compat symlinks

## uncited-behavioural-claim

A comment asserted an ordering the boot does not have: *"runs AFTER the step
above, which is the only thing that legitimately adds a name to the shared tree
during this boot."* `reconcileWorkgroupFsState` is called at `src/main.ts:683`;
`runBootMountQuiescence` at `:693` then calls `reconcileWorkgroupSharedDirs`
(`:515`) and the memory gate (`:521`), both of which add shared names after the
prune has taken its listing. The safety is real but rests on two different
facts — reserved names, and `migrateWorkgroup` writing a shared entry before
its compat link (`shared-dirs.ts:723`/`:731` precede `:742`) — neither of which
was the one claimed. Read the caller before asserting what runs when.

## dishonest-test-oracle

Third, fourth and fifth instances in this module (see `957.md`).

- *"survives a member folder that does not exist yet"* passed with its guard
  removed: the populated member is scanned first, so the assertion's outcome is
  already true before the missing folder throws, and the outer per-workgroup
  catch swallows the throw so `not.toThrow()` holds too. Fixed by asserting the
  workgroup was **not** skipped wholesale.
- *"prunes NOTHING when the shared tree cannot be listed"* passed with the bail
  removed, because the mock called `fs.readdirSync` — by then itself — and the
  member scan died of recursion into its own `try/catch`. **Capture the real
  implementation before `vi.spyOn`**, and assert the doctored call was actually
  made.
- `expect(spy).toHaveBeenCalledWith(...)` after `spy.mockRestore()` always sees
  zero calls. Assert before restoring.

## short-circuit-hides-the-guard

A re-confirm added at review was untestable by the obvious test: the guard sits
*after* `sharedNames.has(name)`, so any fixture with the name in the listing
never reaches it. Killing it needed the name **absent from the listing but real
on disk** — the actual race — with a dangling symlink as the payload, since
that is the only shape where `lstat` (name taken) and `existsSync` (does not
resolve) disagree. When a mutation survives, check whether an earlier clause
short-circuits the one under test before concluding the test is adequate.

## fail-closed-means-cannot-tell

A listing failure must not read as "nothing is there". The shared tree is read
once per workgroup and a failure returns; a per-link `existsSync` would answer
"gone" for every name the instant that tree were unreadable and delete the
workgroup's entire compat layer. Same reason the re-confirm uses `lstat`: the
listing counts a *name*, so a resolving check disagrees with it for an entry
that exists but dangles.
