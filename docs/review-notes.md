# Review notes

Lessons from past reviews, one line each. The author and the reviewer read
this before writing or reviewing code (`docs/review-policy.md`, "Review notes
and fix links"). A PR that received a `changes` receipt adds or amends a line
here, or its body says `Review-notes: none (<reason>)`; `codex-review.sh
merge-check` enforces that. Deferring a finding to an issue, or reverting a
PR, adds a line too.

Format, one line per lesson under Lessons:
`YYYY-MM-DD · PR · class · lesson · structural fix (if any)`. PR is `#<n>`,
several joined with `/`, or `rule`. The class is one of the Classes below. The
structural fix is exactly `none`, or cites the check, test or primitive that
now catches the class: a backtick path, a `file:line`, a `#<n>` or a commit
sha. No line is dated after today.

**The same mistake twice becomes a check.** `scripts/review-notes.test.ts`
fails when a class is on two or more lines and its newest line's structural
fix is `none`. So the PR that records the second occurrence is the one that
must add the lint rule, test or primitive, and name it here. The test also
fails a line out of format, or a class not registered below.

## Classes

Add a class here, in the same PR, only when none of these fits.

- `merge head` — the gate judged one commit and another one merged
- `stream lifetime` — a stream ends while work that answers over it may still run
- `ambient git config` — repository, user or attribute git config (`insteadOf`, `diff.external`, textconv) silently changes what a safety check reads or targets
- `hook tests` — a shared hook or fixture changed, and only one of the test files that cover it ran
- `drift tests` — a drift test hardcodes the list it guards instead of deriving it
- `trusted actors` — a trusted identity is only as narrow as every token that can act as it
- `reviewer tier` — a review from a model tier that may not review
- `enforcement scope` — a control binds only where one mechanism (a hook path, branch protection) happens to run
- `risk coverage` — review skipped a path that needed it; the path belongs on `risk:high`
- `mutation coverage` — a test stays green when the property it names is deleted
- `deferred hardening` — a real finding recorded rather than fixed, with a re-raise trigger
- `fail-open default` — a missing, null, empty or invalid input read as a default that turns the protection off, instead of failing closed
- `timestamp resolution` — second-resolution timestamps read as if they ordered events within one second
- `import-time side effect` — work at module load (a file read, a parse) that can throw and take down every importer
- `stale state` — an artifact left from an earlier mode escapes a check that only looks at new ones
- `pathspec quoting` — paths listed as quoted text, or reused as pathspecs, so special bytes or pathspec magic slip past the check
- `signal handling` — a trap that cleans up but lets the script continue, or a signal lost before an irreversible step
- `over-broad guard` — a fail-closed guard that also refuses a legitimate state, blocking all the work instead of one bad input
- `test synchronization` — a test barrier or wait that does not order what it claims to, or falls through silently on timeout
- `usage exit code` — a bad invocation exits with the read-failure code instead of the documented usage code
- `metric definition` — a measurement script judges a historical PR by today's state or rules instead of the rules that actually applied at its own merge
- `silent cap` — an upstream listing silently stops at its own hard result cap and hands back a valid-looking but incomplete result with no error; a count at the cap must fail closed, never pass as complete
