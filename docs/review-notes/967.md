A name reservation is not a content reservation: `rename(2)` replaces a file silently, so every site that renamed onto a claimed name had to re-derive by hand whether the name still held only the claim, and each patch moved the window instead of closing it. When the same class recurs at a new site each round, stop guarding call sites and change the primitive so there is no window to guard · files are published with `linkSync`, which fails `EEXIST` in the kernel so the name appears only with the content in it; the file claim, `claimSharedName`, `releaseClaim` and the size-zero release guard are deleted, and directories keep claim-then-rename only because `ENOTEMPTY` is already the kernel's refusal (`src/modules/workgroup/shared-dirs.ts` `publishFile`/`publishDir`). The first attempt at the fix moved the hole rather than closing it — `link(src, dst)` then `unlink(src)` removes whatever is at that PATH, not the inode just linked, so a live member saving the file atomically between the two calls lost its new version while the shared tree kept the old one (round 1, reproduced). Publishing now takes the member-side name first (`rename` to `.<name>.publishing`), links the held bytes, then drops the hold — a reservation on each side of the move. Round 2 then found the class a SIXTH time in the helper written to undo a hold: `lstat(real)` then `rename(held, real)` destroyed a member save made inside that window, so giving a hold back is `link` + `EEXIST` too. Round 3 then found it a SEVENTH time, in the hold's own creation: `rename(2)` cannot refuse an occupied name, so the `lstat` in front of it was the guard, and a member writing at the hold path inside that window lost those bytes. There is no `renameat2(RENAME_NOREPLACE)` in Node, so that site could not be made to refuse — the target is made UNFORGEABLE instead (48 random bits, matched next boot by pattern rather than derived), which deletes the check, its test, and the "a member dotfile may lose its name" limit at once. The lesson the rounds share: every name this code takes must be taken by a syscall that refuses, and where no such syscall exists the name must be one no other process can hold.
