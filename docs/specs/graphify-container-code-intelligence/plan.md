### Task A1: Implement the enforcing freshness gateway

**File:** `container/graphify-gateway.py`
**Operation:** CREATE
**Test file:** `container/tests/test_graphify_gateway.py`

**Approach:** Build a standard-library-only supervisor that owns command policy, repository/cache identity, source inventory, stable locks, immutable snapshot capture, AST-cache seeding, bounded staging, recovery, promotion, and worker deadlines. This follows the `agentic-systems` capability-boundary pattern: the safe invariant is enforced by the tool boundary instead of prompt compliance. Graphify package imports stay in the private worker; the gateway carries a pinned extension/extractor contract whose drift is tested in A3.

**Interface / signature:**

```text
main(argv: Sequence[str] | None = None) -> int
parse_public_command(argv: Sequence[str]) -> QueryCommand
resolve_managed_repo(cwd: Path) -> ManagedRepo
inventory_source(repo_root: Path) -> SourceGeneration
refresh_index(repo: ManagedRepo, generation: SourceGeneration, command: QueryCommand) -> int

QueryCommand.command = "query" | "path" | "explain" | "affected" | "help" | "version"
SourceGeneration = {fingerprint, files[{path, sha256, md5, bytes, graphify_hash}], total_bytes}
AcceptedSourceState = {graphify_version, fingerprint, files, total_bytes, accepted_at}
```

ASSERT: only `query`, `path`, `explain`, `affected`, help, and version are accepted; `extract`, `update`, `watch`, hooks, MCP/global commands, `--graph`, `--out`, `GRAPHIFY_OUT`, and any user-selected cache/output path cannot bypass the gateway.
ASSERT: help and version are side-effect-free fast paths: they do not resolve Git/repository identity, create cache or runtime directories, acquire either lock, inventory source, or spawn the worker.
ASSERT: the current directory must resolve through Git to one real repository directly below `/workspace/worktrees`; symlink escape, nested arbitrary roots, missing worktree, unreadable paths, walk errors, files over 5 MiB, more than 4,000 detected code files, or more than 64 MiB aggregate input fail before Graphify runs.
ASSERT: every detected file, including intentional data JSON, participates in the sorted SHA-256 generation fingerprint; capital-F Fortran (`.F`, `.F90`, `.F95`, `.F03`, `.F08`) and detected languages without an in-process extractor fail closed.
ASSERT: a changed source generation is copied to a private immutable stage, rehashed, and compared to a fresh live inventory; Graphify never reads a prior live tree after changed content is observed.
ASSERT: changed refresh may retry at most twice and shares one 900-second monotonic budget across cache-lock wait, global-worker wait, admission, capture, extraction, validation, and promotion.
ASSERT: the stable per-cache `fcntl.flock` is acquired by nonblocking polling within the shared monotonic budget, and kernel release after process exit is the only stale-owner cleanup; the host-wide `/run/nanoclaw-graphify/worker.lock` is held in the design order, every extract and cached query holds it, and cached queries acquire it before their final two equal live inventories.
ASSERT: admission reads cgroup v2 `memory.current` and `memory.max` and requires 1,024 MiB worker allowance + 384 MiB output/stage allowance + 512 MiB protected runner reserve below the hard limit; `requestMb` is not treated as the burst ceiling.
ASSERT: `/workspace/.graphify-stage` is emptied per attempt; only exact current `v0.9.16` AST hashes are seeded, and reuse additionally requires exact-case path continuity with no prior/current case-fold collision.
ASSERT: prior graph, manifest, status, stat index, obsolete hashes, other extractor versions, and temporary files are never seeded into a changed candidate; seeded AST bytes are capped at 128 MiB.
ASSERT: after extraction, a fresh live inventory must equal the captured generation; mismatch deletes the candidate and retries. Before promotion the private `stage/source` snapshot is removed, and the supervisor validates bounded file sizes/hashes by streaming rather than loading graph content.
ASSERT: promotion is rename-based on one host filesystem (`live → backup`, complete output/status/source-state stage → `live`); it provides process-atomic namespace visibility but does not claim power-loss durability. Failed refresh/query never reads stale `live`, failed candidates are deleted, backup recovery is validated, and diagnostics retain at most two 64 KiB metadata-only records.
ASSERT: at most one persistent `live`, one host `stage`, one transient `backup`, one 192 MiB tmpfs generation, and two capped diagnostic records exist per cache; success and every failure remove source snapshots and abandoned output.
ASSERT: the 120-second query budget includes worker-lock wait, final inventories, worker execution, and teardown. On any refresh or query expiry, the supervisor sends SIGTERM to the worker process group, waits five seconds by default, then sends SIGKILL and reaps it before releasing locks.
ASSERT: stderr telemetry contains durations, sizes, waits, mode, retry, worker RSS and virtual size, cgroup memory, tmpfs high-water, and terminal reason but never query text, source contents, credentials, or hidden upstream query history.

### Task A2: Implement the kernel-bounded private worker

**File:** `container/graphify-worker.py`
**Operation:** CREATE
**Test file:** `container/tests/test_graphify_worker.py`

**Approach:** Implement a private JSON-descriptor-driven worker for `extract` and the four read commands. It sets native thread environment variables and all kernel limits before importing any Graphify or numerical module, invokes only the pinned in-process paths, captures diagnostics, validates exact generation coverage, and writes one machine status file. The parent gateway remains outside these limits so a refused allocation/task/file cannot kill the agent runner or corrupt promotion state.

**Interface / signature:**

```text
main(argv: Sequence[str] | None = None) -> int
apply_limits(address_space_bytes: int, file_bytes: int, process_count: int) -> None
extract_candidate(descriptor: ExtractDescriptor) -> WorkerResult
run_query(descriptor: QueryDescriptor) -> WorkerResult
validate_candidate(source: SourceGeneration, out_dir: Path, diagnostics: Diagnostics) -> ExtractionStatus

ExtractionStatus = {detected[], applicable[], intentional_exclusions[], contributed[], unsupported[], failed[], graph_sha256, manifest_sha256}
```

ASSERT: `OPENBLAS_NUM_THREADS`, `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `NUMEXPR_NUM_THREADS`, and equivalent native thread knobs are `1`, then `RLIMIT_AS=1,024 MiB`, `RLIMIT_FSIZE=64 MiB`, and `RLIMIT_NPROC=0` are applied before the first Graphify import.
ASSERT: extract invokes patched Graphify `v0.9.16` code-only mode in-process with `NANOCLAW_GRAPHIFY_SEQUENTIAL=1`, `--max-workers 1`, query logging disabled, private source root, and tmpfs output; query invokes only the gateway-selected accepted graph.
ASSERT: worker never starts a subprocess or Python/native thread; any unclassified fork/thread attempt receives the kernel refusal and produces a structured failure.
ASSERT: only the pinned JSON extractor's exact `skipped: data json` result is intentional non-applicability; every other detected source is applicable and must contribute at least one normalized `source_file` node.
ASSERT: `contributed == applicable`, `detected - contributed == intentional_exclusions`, and `unsupported == failed == []`; graph has `nodes`/`links`, paths remain inside the immutable generation, manifest MD5s equal source state, graph ≤64 MiB, AST cache ≤128 MiB, and aggregate tmpfs ≤192 MiB.
ASSERT: nonzero exits, invalid JSON/schema, walk/worker/zero-node/no-extractor/missing-dependency/AST-pass/manifest/cross-file diagnostics, hash mismatch, ENOSPC, and limit breaches are failures even when upstream would otherwise continue or exit zero.
ASSERT: worker output never includes source text or query history and cannot write to the live persistent cache directly.
ASSERT: the worker is always started in its own process group by the gateway; both extract and query use the gateway's TERM → five-second grace → KILL deadline contract, and no killed or SIGTERM-ignoring worker survives.


ASSERT: patch applies cleanly to `graphifyy==0.9.16` and fails on missing/drifted context or any other installed version.
ASSERT: NanoClaw mode passes `parallel=False` for AST extraction and avoids `ThreadPoolExecutor` for manifest hashes; non-NanoClaw behavior remains upstream-compatible.
ASSERT: source IDs/cache hashes stay anchored to the immutable source root while AST files are written to the external tmpfs cache.
ASSERT: contract audit pins the exact `CODE_EXTENSIONS`, extractor dispatch coverage, lowercase path/content hash algorithm, exact data-JSON skip, capital-F Fortran subprocess, manifest thread pool, export Git metadata probe, and every extraction diagnostic accepted/rejected by A2.

### Task A4: Lock and audit the ARM64 wheel-only dependency closure

**Files:** `container/graphify-requirements.lock`, `container/graphify-wheel-audit.json`
**Operation:** CREATE
**Test file:** `container/tests/test_graphify_supply_chain.py`

**Approach:** Resolve `graphifyy==0.9.16` for the production Linux ARM64/Python 3.11 target using a recorded uv version and the fixed `--exclude-newer 2026-07-15T16:36:30Z` cutoff (approved design time minus 72 hours). Commit every exact version/hash plus a machine-readable audit of the selected wheel filename, architecture tags, SHA-256, and upload timestamp; image installation remains pip `--require-hashes --only-binary=:all: --no-deps` so no build backend executes.

**Interface / signature:**

```text
graphify-requirements.lock: exact `name==version --hash=sha256:...` records only
graphify-wheel-audit.json: {uv_version, python_version, platform, cutoff="2026-07-15T16:36:30Z", generated_at, wheels[{package, version, filename, sha256, uploaded_at}]}
verify_lock(lock_path: Path, audit_path: Path) -> VerificationResult
```
