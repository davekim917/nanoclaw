## Brief Reference

This implements the approved [`brief.md`](./brief.md): one Markdown memory canon
per workgroup, automatic relevant recall and actual session capabilities before
every provider response, and lossless customization-first migration.

This file records the pre-curator shared-canon design. It is retained for
provenance and is non-normative where the approved plan differs. The discarded
accreted coordinator/audience/ledger machinery remains historical only.

### Flagged and Demoted Prior Constraints

- Automatic semantic fact capture is out. `archive.db` preserves exact
  provenance; curated Markdown is the only distilled memory.
- A host-only coordinated writer is out because it breaks protected direct
  Markdown editing. In-tree helpers use temp-file-plus-rename; arbitrary
  simultaneous same-file edits retain ordinary last-writer semantics.
- Intra-workgroup principal/conversation algebra is out. Workgroups are already
  the archive/files/Graphify sharing boundary; owner-safety still controls
  capability disclosure.
- Admission grants, spawn/delivery protocols, COW registries, declassification,
  credential redesign, and Graphify authorization redesign are unrelated.
- Provider registration needs parity tests, not a new conformance subsystem.

## Options

### Option A: Shared Filesystem plus Paired Pre-Turn Row

Put canon at `data/workgroups/<id>/memory`, retain every provider's existing
memory path via compatibility link, and build bounded pre-turn context at
`writeSessionMessageInternal` from Markdown, host archive, and actual
capabilities.

- **Pros:** restores the removed behavior at existing seams; preserves direct
  edits; adds no schema, transport, daemon, coordinator, or authority.
- **Cons:** helper-mediated writes serialize at workgroup scope; raw shell edits
  retain ordinary filesystem semantics; direct scans need bounds.
- **Pattern alignment:** exact reuse of the researched mount, FTS, capability,
  and recall-row paths.
- **Confidence:** High.
- **Assumptions:** A1-A3 below.

### Option B: New Host Memory Authority

Keep canon host-only behind a coordinator, ledger, mutation protocol, and
read-only projections.

- **Pros:** serializes every write and can attach policy metadata.
- **Cons:** breaks direct editing and creates schema/protocol/recovery machinery
  for hypothetical concurrency and audience systems.
- **Pattern alignment:** poor; violates C1, C7, and brief non-goals.
- **Confidence:** Low.
- **Assumption:** users accept losing direct Markdown edits; they do not.

### Option C: Group Copies plus Provider/Graphify Pull

Keep group-local stores and synchronize them or ask providers/Graphify to search.

- **Pros:** little filesystem migration.
- **Cons:** copies diverge; optional tool use and Graphify misses caused the
  incidents; resets still lose facts unless the model searches.
- **Pattern alignment:** contradicts C2.
- **Confidence:** High that it is invalid.
- **Assumption:** derived retrieval and model tool use are reliable; production
  evidence disproves this.

## Recommendation

**Select Option A.** It alone provides one canon, every-turn source context,
provider parity, and customization preservation through existing mechanisms.
A single kernel lock for the low-rate helper path prevents sibling write races
without adding a distributed writer, schema, daemon, or recovery protocol.
Explicit raw shell edits retain ordinary shared-filesystem semantics.

### 1. Canon and Compatibility

- Canon: `data/workgroups/<workgroup-id>/memory`.
- Container canon: `/workspace/workgroup/memory`.
- Existing `/workspace/agent/memory` becomes a reconciler-style
  container-absolute compatibility link for every sibling.
- Startup, group init, and spawn automatically reconcile only missing paths and
  exact shipped scaffolds for every current or future sibling. Any substantive
  or ambiguous local tree fails closed to the quiescent lossless migrator in
  section 4; only its verified cutover may import bytes and replace that path
  with the compatibility link. Host tools/skills use the canonical host path
  and never dereference the intentionally dangling host-side provider link.
- `ensureMemoryScaffold()` continues unchanged through that link and creates
  only missing files.
- Prompts, identity, `CLAUDE.local.md`, config, credentials, provider state,
  repos, worktrees, and all non-memory files remain untouched.
- All providers use one `[NEW] write_memory_file` command. The host creates one
  stable workgroup lock sidecar outside the memory canon with `wx`, validates it
  as a no-follow regular file, and always bind-mounts that exact inode read-write
  at `/workspace/workgroup/.memory-write.lock` for every sibling and mount mode.
  The command takes a bounded nonblocking kernel `flock` and holds it across
  expected-SHA validation, temp write/fsync, recheck, descriptor-anchored rename,
  and parent fsync. One low-rate workgroup writer at a time is deliberate
  simplicity; process death releases the kernel lock, with no time/PID stealing
  or second fence. New notes use unique create-only names. Provider instructions
  require this command; raw shell edit remains an explicit ordinary-filesystem
  escape hatch. No service or schema is added.

### 2. One Pre-Turn Context Builder

Add `[NEW] buildPreTurnContext`, owned by the host memory module and called by
`writeSessionMessageInternal`. It receives the normalized inbound row/content
as **untrusted query input**, plus trusted `agentGroupId`/`sessionId`; scope,
members, messaging group, and owner-safety come only from host DB state.
Pair context only when a host helper equivalent to the runner's
`isAdmissibleTrigger` says the normalized row can invoke a provider.

It returns one bounded block:

1. **Trusted runtime state:** rendered
   `buildSessionServicesSnapshot(agentGroupId, messagingGroupId)`.
2. **Canonical memory:** always-loaded core plus relevant deeper Markdown,
   selected deterministically from sorted `.md` paths, headings, and content.
3. **Conversation evidence:** exact current-thread rows first, then workgroup
   FTS candidates. Pasted Slack/Discord URLs use the existing exact parser/query
   before general search.
4. **Status:** explicit no-match or degraded-source notices; a read failure is
   never presented as complete recall.

Named constants bound files, scanned bytes, candidates, excerpts, and final
characters, with deterministic truncation markers. Defaults are chosen only
after measuring the live corpus. Current input wins; canonical Markdown is the
distilled source, while material archive conflicts are shown rather than
silently resolved.

Trusted capability state and untrusted recall are separate structured fields.
Every memory/archive excerpt and provenance string is serialized as a JSON
string (or equivalently collision-safe value), never concatenated into trusted
markup; formatter output preserves that separation. Fixtures include delimiter,
JSON, tag, and fake-capability-section payloads.

Markdown, archive, exact-link, and capability-detail reads each have independent
bounds and exception handling. Each failure contributes its own degraded notice
while other sources and the trigger proceed. Only inability to resolve trusted
group/session scope blocks ingress; the builder otherwise always returns a
paired row.

### 3. Paired Inbound Write and Continuity

For trigger `<id>`, insert `recall-<id>` immediately before it in one
`inbound.db` transaction. Keep subtype `recall_context`, reusing runner ordering,
pairing, filtering, warm-continuation push, and orphan handling. Duplicate
ingress inserts neither row twice.

Runner selection applies `maxMessagesPerPrompt` to logical trigger units, or
fetches the missing partner after selection: a prompt may contain both
`recall-<id>` and `<id>`, or neither, never a boundary-truncated half-pair.

Because this happens before every response, first wake, warm continuation,
compaction, rotation, and replacement receive fresh authoritative context.
Provider recap/native history stays supplemental. `get_capabilities`, thread
tools, and Graphify remain diagnostic/deeper-exploration tools, not
first-response prerequisites. The group-level capability fragment must not
claim session accuracy.

Breaking-memory activation also reconciles already-live queue state. After all
selected workgroups reach `applied`, insert fresh pairs for admissible pending
or processing non-scheduled triggers before service activation; startup repeats
the same operation idempotently before channel startup as crash recovery.
Scheduled tasks are not paired at upgrade time: their existing due-time
admission seam demotes any legacy unpaired row and rebuilds current context when
the task is actually due. Terminal pre-activation history is not rewritten.

### 4. Lossless Migration

Read-only preview inventory may discover and hash live sources, but it
authorizes no mutation. For each workgroup, before snapshot or path cutover:

1. Strictly clean install-scoped orphan containers and verify no affected
   container remains. Cleanup or absence-verification failure stops migration.
   Manual cutover uses the same stop/cleanup/absence proof.
2. Discover every member `groups/*/memory` and recognized provider-native memory
   source at execution time; record source type, path, file type, size, SHA-256.
3. Copy every byte to a permanent host-only timestamped rollback snapshot and
   verify it against the manifest.
4. Treat a tree as empty only when every path/byte equals shipped templates. A
   one-byte difference is substantive. Preserve opaque provider sources in the
   snapshot/report, but do not activate them as another authority.
5. Choose base deterministically: verified existing canon, else workgroup-slug
   sibling, else lexical source order. Place each remaining source as one
   coherent tree: direct only when the complete tree fits, otherwise at its
   exact pre-existing or deterministic `imports/<source-group>/` root. Exact
   whole-tree duplicates may share one root with all origins retained.
   Leaf-by-leaf placement and deduplication are forbidden because relative
   Markdown links and customizations depend on a common path context.
6. Copy absent trees without overwrite. If the deterministic import root is
   customized, preserve the complete source under a deterministic
   SHA-qualified tree collision. Direct recall scans every retained tree.
7. Write a checksummed source-to-destination report and verify canon and rollback
   coverage for every input byte.
8. Reverify absence, then rehash all sources immediately before link replacement;
   any container or byte change aborts without replacing paths.
9. Only then replace sibling memory paths with compatibility links. Rollback
   material has no automatic cleanup.

The report and runtime verifier resolve every inventoried relative Markdown
link through both the snapshot source tree and its canonical outcome mapping.
Any changed target is activation-blocking. Any discovery, copy, collision,
checksum, unsupported-file, or link failure
blocks that workgroup's cutover. Rollback restores source trees from the
manifest; canon may remain unreferenced for forensic comparison.

## Recall Evaluation Gate

Use a versioned fixture corpus with exact current-thread facts, paraphrases,
cross-thread facts, distractors, corrections, pasted links, and legitimate
no-match prompts. Run it as the first implementation spike. Direct bounded
lexical lookup is the default and must achieve:

- 100% recall for exact current-thread facts, explicit corrections, and exact
  pasted-link fixtures;
- at least 90% top-context recall for paraphrase and cross-thread fixtures;
- at most 5% distractor false-positive injection; and
- 100% explicit no-match behavior with zero fabricated excerpts.

Tune tokenization, lexical scoring, source preference, and bounds against this
corpus. If lexical lookup misses the gate, bounded ephemeral expansion of only
the current query may feed the same authoritative lookup; it is never persisted
or treated as evidence. Re-run unchanged thresholds and stop if they still fail.

Provider behavioral fixtures also inject recalled instructions, fake capability
claims, and tool/action requests across repeated trials. Providers must treat
them only as evidence and perform no unauthorized action; deterministic host
guards remain the authority. No fixture authorizes a semantic store/index.
