# Observatory / Signal

Observatory supervises autonomous work across the authenticated user's workspaces. Signal is the default overview, with Projects, Decisions, Agents, Threads and Schedule destinations. Every displayed record comes from the authenticated APIs; empty and partial coverage remain distinct.

The overview opens a compact decision queue beside one selected decision workspace. Source-declared release blockers, changed evidence, awaiting decisions and reviewed records have separate groups. Queue rows show exact questions with source age and review ownership. Previous-visit chips describe newly observed or changed records, never invented creation dates. Projects remain a separate destination with explicit goals and source next steps. Unmapped work stays visible. Project mappings are persisted by owner/global administrators through the Projects form using exact repositories and a friendly channel-name picker that persists channel keys. Mapped projects appear first; compact workspace-labelled unmapped rows retain the remaining coverage. Missing goals, owners and dependencies are stated; an unknown dependency is never represented as checked independence. Declared dependency IDs resolve only to exact visible source items in the same workspace; unresolved or ambiguous references stay explicit.

The decision inbox preserves release items of all kinds, thread questions and actual privileged approval metadata. Selecting a record reads its exact context and evidence. Long source text uses exact excerpts with expandable full content. Open, My reviews, Unclaimed and Recorded filters narrow the inbox. Initial selection prioritizes source-declared release blockers and changed evidence among unanswered records. Reviewers claim/release ownership and record a version-bound answer with conflict handling. Saving an answer sends nothing. Sending requires a separate action and explicit agent selection. Unanchored release items additionally require an existing destination thread in the same workspace. Pending delivery retains its reserved recipient and evidence for retries. Sent instructions do not imply completed agent work.

Privileged approvals link to their original authorization destination and offer no generic approval mutation. All authorization remains server-side; review assignment does not grant authority.

Agents open a selected work summary: the first three source claim notes, expandable identifiers, exactly associated open and recorded decisions, scheduled work, and secondary conversation evidence. Recorded decisions are not work outcomes.

Threads open a contextual work brief with an explicitly mapped objective when available, current state, related decisions, source participants and agent-reported completion proposals. Recent conversation is an optional tab. A recipient-specific composer sends through the existing safe API; unresolved sends retain immutable payloads and delivery keys across thread navigation. Snooze and guarded close remain available. The complete operational console, including assignment and scheduling behavior, is secondary under Full conversation. Exact `#/threads/<encoded thread ID>` bookmarks request that thread directly, even if outside the current queue window. Schedule supports both `#/schedule` and the existing `#/scheduled` bookmark.

Search filters the current source-backed view. The workspace selector includes all visible workspaces and an all-workspaces option. SSE bursts coalesce; reconnect and focus revalidate. A 30-second refresh covers filesystem release sources. Signal timestamps use the authoritative install timezone returned by the server, with the zone labelled in the timeline and footer; no browser-zone fallback is used. Loading, initial failure, refresh failure, disconnection and stale/unavailable sources are visibly distinct. Decision actions pause on a failed exact-context refresh.

Desktop uses the Signal rail and two-column work/decision layout. Mobile places a bounded selectable queue above the selected context while retaining all navigation and actions. Fonts are locally bundled Geist and Geist Mono. No external font requests, purple, gradients or fictional runtime records.

Historical threads load in explicit 200-record workspace pages. Coverage controls disclose when more records exist; counts and search represent loaded thread pages while release-source records remain complete. Additional pages merge by exact IDs. Refresh resets pagination to the latest first page and request failures preserve loaded records. Direct decision links request the exact ID even outside loaded pages.
