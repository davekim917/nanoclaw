- **Class:** DIVERGED
- **Acknowledged:** YES — see `drift-acks.json` entry `B1`.

### [B2] `buildCentralProjection` widening — Research Summary vs M5 table

- **Class:** DIVERGED

### [B4] `onecli_secrets` storage shape — JSON objects vs string array

- **SOT claim:** Design § "OneCLI secret merge semantics (D8, refined)" says resolved UUIDs are stored "as JSON `[{name, uuid}]`".
- **Target:** Plan Task C4 stores names as `string[]` (e.g., `["Anthropic","Exa"]`).
- **Why DIVERGED:** Plan uses simpler `string[]` form. `applyOnecliSecrets` (`src/onecli-secrets.ts:181`) accepts either names or UUIDs and resolves with caching (`identifierToUuid` map at `:54`). Performance parity for MVP; simpler shape; one less migration step if the format changes later.
- **Class:** DIVERGED
- **Acknowledged:** YES — see `drift-acks.json` entry `B4`. Rationale: MVP simplification; existing cache in `onecli-secrets.ts` gives equivalent perf without the schema complexity. Design will be updated post-build to reflect actual shape.

### [B5] E1 writes `recall_scope: 'workgroup'` to BOTH members — design says "every auto-paired group" but condition is `workgroup_id !== folder`

- **SOT claim:** Codex (Agent B) flagged that design says "every auto-paired group's container.json" gets the write (implying both members of each pair).
- **Target:** Plan Task E1 condition `workgroup_id !== folder` only matches children (helper-codex), not parents (helper has `workgroup_id === folder`).
- **Why DIVERGED:** Investigated. The parent's `agent_groups.id` (e.g., `ag-1700000000000-example01` for helper) IS the `workgroups.mnemon_store_id` for the workgroup. When helper recalls with `'self'` mode, it resolves to `[ag-1700000000000-example01]` which IS the workgroup canonical store. So functionally, `'self'` and `'workgroup'` produce identical store IDs for the parent. Only the codex twin (whose `agent_groups.id = "example-labs-codex"` ≠ workgroup store id) needs the explicit `recall_scope: 'workgroup'` write to redirect to the canonical store. Plan correctly applies the write only where it has effect.
- **Class:** DIVERGED (surface-level; functionally CONFIRMED)
- **Acknowledged:** YES — see `drift-acks.json` entry `B5`. Investigation note: design text "every auto-paired group" is informal; the condition `workgroup_id !== folder` is the operational definition the plan correctly implements.
