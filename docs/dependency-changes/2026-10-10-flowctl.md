# Estuary flowctl in the agent image

flowctl joins the image so an agent group that declares the `flowctl` tool can run it as an Estuary service
account. It is new to the image, so every behaviour below is new to the fleet.

## docker:flowctl none → 0.6.13

Source: https://github.com/estuary/flow/releases/tag/v0.6.13, crates/flowctl and crates/flow-client-next at v0.6.13

- the binary installs only on amd64 (upstream ships no arm64 build) and only when its bytes match the asset digest GitHub records for the release · not covered: an image build property, checked by `sha256sum -c` and `flowctl --version` in the Dockerfile itself
- `FLOW_AUTH_TOKEN` authenticates it, a refresh token exchanged in a request body; only a group naming `flowctl` in `tools` receives one, from its folder-scoped host key · test: src/flowctl-credential.test.ts
- its HTTP client trusts only bundled roots, so Estuary hosts bypass the OneCLI proxy · not covered: needs a running gateway; host steps verify it with a live `flowctl catalog list`
- a later release bump reads its pinned digest from the GitHub release document · test: src/container-updates.test.ts
