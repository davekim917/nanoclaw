## Validator CD findings

### MUST-FIX (BUG class — review-swarm)

**[CD-1] buildArchiveProjection workgroup-widening never activated in production — FIXED in ac41dae**

The function checked for `agent_groups` table inside `archive.db` (the source); if absent, fell through to single-agent legacy filter. But `archive.db` is created by `src/message-archive.ts` and contains only `messages_archive` + FTS — never `agent_groups`. So production calls never hit the workgroup branch; R5 (chat archive widens to workgroup) was never delivered.

**Fix:** moved workgroup membership resolution to the caller (`container-runner.ts` spawn path), which has central-DB access. Added optional `workgroupMemberIds?: string[]` parameter to `buildArchiveProjection`; uses parameterized `WHERE agent_group_id IN (...)`. W3 fail-closed also moved to the caller — projection no longer inspects archive schema for workgroup_id existence. Tests updated to pass member IDs explicitly.

**[CD-2] Mnemon classifier writes went to per-agent stores, not workgroup canonical — FIXED in ac41dae**

`MnemonStore.remember` used the raw `agentGroupId` as `--store`, so daemon-extracted facts from `helper-codex` landed in its own (empty) store rather than the workgroup canonical (`workgroups.mnemon_store_id`). Read-write asymmetry — container reads from canonical, daemon writes elsewhere.

**Fix:** `MnemonStore.remember` now calls `resolveWorkgroupStoreId(agentGroupId)` before the mnemon CLI invocation; falls back to `agentGroupId` on error (test contexts without workgroups schema).

**[CD-3] Non-W3 errors silently produced empty projection (fail-open) — FIXED in this commit**

The catch block in `buildArchiveProjection` re-threw only when the error message included `'workgroup_id is NULL'`. Other failure modes (SQL parse error, SQLite lock, etc.) were logged and swallowed; the destination DB stayed initialized-but-empty. Container mounted an empty archive.db and queries returned no rows silently.

**Fix:** unconditional re-throw in the catch block. Caller (container-runner spawn) sees the failure and aborts the spawn. Fail-closed posture restored. After CD-1 the W3-specific check moved to the caller anyway, so the catch block doesn't need special-case discrimination.

**[CD-4] Spawn-order race in `ON CONFLICT DO NOTHING` reconciler — ACCEPTED with mitigation**

If a codex twin spawns BEFORE its parent's `agent_groups` row exists (e.g., a future provisioning workflow that creates a sibling without a pre-existing parent), the reconciler's `INSERT ... ON CONFLICT DO NOTHING` locks `workgroups.mnemon_store_id` to the codex twin's own id. Subsequent parent spawn no-ops on the conflict; the workgroup is permanently pointed at the wrong store.

**Mitigation today:** The `clone-as-codex` skill (per its SKILL.md) enforces a parent-first invariant — the parent's `agent_groups` row always exists before the codex sibling is created. Practical exposure on Operator's install is zero.

**Status:** ACCEPTED as known limitation. Documented in `docs/workgroups.md` § Staleness window. If a future provisioning flow violates parent-first, the operator can manually `pnpm exec tsx scripts/q.ts data/v2.db "UPDATE workgroups SET mnemon_store_id = ? WHERE id = ?"` to fix. Long-term fix (deferred follow-up): change reconciler to detect mis-pinned `mnemon_store_id` and self-heal on subsequent spawn.

### SHOULD-FIX (SUGGESTION class — review-swarm)

**[CD-5] `require()` in scope-resolver — FIXED in ac41dae**

Two `require()` calls with eslint-disable comments in `openCentralDb`. CLAUDE.md "Module System (host)" hard rule forbids `require()` because it's `undefined` in built ESM (typechecks but throws at runtime). The lazy-import justification didn't apply — `DATA_DIR` and `better-sqlite3` are both eagerly available at module load.

**Fix:** converted to top-level imports.

**[CD-6] `'workgroup'` scope mode not cached — DEFERRED**

The 60s `scopeCache` is only used for `'all-groups'` and `string[]` modes. Workgroup mode does two DB queries per call without caching. At recall frequency (~1 per chat turn) the overhead is real.

**Status:** Deferred to follow-up. Practical impact at Operator's scale (~30 agent_groups, ~10 workgroups) is microseconds per call. A future optimization can add `'workgroup'` caching with the same TTL.

**[CD-7] Cross-table subquery in projection — DEFERRED**

After the CD-1 fix, the projection now uses a parameterized `IN` list with pre-resolved member IDs, so the originally-flagged triple-nested subquery is gone. The CD-1 fix subsumed CD-7. **Mark as RESOLVED transitively.**

**[CD-8] `resolveSecretUuids` double-exported — FIXED in ac41dae**

Function was exported both via the `__test` namespace and a separate top-level `export { resolveSecretUuids }`. Cleaned up — single top-level `export` declaration; removed from `__test` namespace.

**[CD-9] `reconcileWorkgroupFsState` marked `async` without `await` — FIXED in ac41dae**

Function declared `async` but body was entirely synchronous (`fs.writeFileSync`, sync DB calls). Misleading signature; downstream `await` calls had no effect.

**Fix:** dropped `async` keyword and `Promise<void>` return type. Updated `src/index.ts` call site and test from `await expect(...).rejects.toThrow()` to `expect(() => ...).toThrow()`.
