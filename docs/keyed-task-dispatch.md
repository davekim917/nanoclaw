# Keyed task phases

`ncl tasks dispatch --context-key <phase> --event-key <event> --prompt <brief>` admits an immediate one-shot in the existing isolated task-session path. Keys are scoped to the caller's authorized agent group. A context identifies one bounded work phase or observation; a new unrelated phase needs a new context. Same-phase retries retain their session and workers.

Admission is durable, not a successful-work receipt. Repeating an event returns its original row and status. Changed content under that key, or changed routing/origin within the context, is refused. The mailbox writer checks and inserts in one immediate transaction after the normal quiet-cache invalidation. It writes an inert task for ordinary host admission. No task model or effort override is introduced.

Keys accept 1–200 ASCII letters, digits, `. _ : / # -`, beginning with a letter or digit. Prompts accept 1–64,000 characters. The command supports normal scoped task routing, `--mute-chat` and `--quiet-status`, and has no script, recurrence, model, effort or arbitrary session flag.

`--retry-of <event>` admits a recovery only after a failed or expired predecessor, or a completed delivery with an exact automatic provider-error outcome. Host execution must be idle with no outstanding inputs/actions or continuation. Each predecessor has at most one recovery, and a chain allows two recoveries. Successful completed events and cancelled events cannot recover. Missing execution or outcome evidence defers recovery. Explicit new work has its own event identity; the recovery cap is not a fleet wake budget.

`ncl tasks get --id <event-row> --session <session> --settlement` returns host-owned execution/outcome facts. Settled means exact successful automatic outcome plus the shared task-idle conjunction and no future/paused inputs or undelivered system actions. It does not interpret artifacts or grant publication authority. A controller must separately accept the phase's durable artifact contract. Older uncorrelated and batched outcomes cannot settle an individual event.

For migration of a legacy recurring observer only, `--observer-settlement` excludes future **inert, pending recurrences of the selected row's exact series and schedule in its matching task session**. Due polls, admitted polls, paused rows, one-shots, self-wakes, claims, background execution and continuation still block. This allows the old observer to finish on its own route without mistaking its next clock tick for an active worker. It does not turn an unknown historical outcome into success.

For an observer whose follow-ups are separate episodes, `--future-inputs-settled` sets aside pending inputs that are **not yet due** (for example a deadline `wait` the observation turn armed for a different work item, and its recall row) and reports their count as `futureInputs`. It combines with `--observer-settlement`. Due, undated, paused and processing inputs, claims, provider execution, continuation and undelivered actions still block, and it never turns an unknown or failed outcome into success. The set-aside wakes still fire later in their own session. A phase whose own waits are part of the phase — a smoke campaign step — must not use it.

The QA controller's optional `SMOKE_CONTROLLER_OWNER_DISPATCH_CUTOVER_JSON` points to `{ "enabled": true, "legacyRuns": [...] }`. Existing owner obligations and listed campaigns retain the legacy route; new campaigns persist their phase route in the existing journal. Turning the option off prevents new routes while persisted phase owners finish. Internal phases are muted and quiet; the controller remains the sole campaign reporter. No active session is reset or transferred.

Automatic spent-task session closure retains sessions containing keyed event receipts, including terminal events. Containers still idle-reap normally. This retains the central session row and its mailbox files for every keyed context; storage and session enumeration therefore grow with dispatched phases. No retention cleaner or separate permanent tombstone store is added. Manual deletion or closure of these sessions ends deduplication and must wait until no producer can replay their keys. Natural provider-context isolation and outcome savings require observation after deployment; source tests alone do not establish either.
