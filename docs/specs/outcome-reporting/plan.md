# Outcome-first work-item reporting

Authorized outcome: useful autonomous work continues quietly. Developers receive one concise contextual report when each original human work item finishes, can request detail or steer, and still receive material incidents, genuinely blocking product/trust/authority decisions and required approvals. No global wake budget, model change, new evaluator, periodic public digest or widened authority.

## Implementation contract

- Existing container.json has optional outcomeReporting=true and outcomeReportingExternalChannels. Absent/false leaves other groups unchanged. A spawn-only NANOCLAW_OUTCOME_REPORTING=1 capability activates the shared runner/MCP behavior; old live containers retain their legacy human-reply path. Both Claude and Codex get the same generated output instructions. Existing NANOCLAW environment forwarding reaches the built-in MCP subprocess.
- Existing send_message accepts purpose: progress/outcome/reply/urgent/decision/handoff. Under opt-in, channel sends require purpose; progress writes work_log instead of chat. Internal agent destinations keep their existing routing and permissions. Human requested replies can be detailed; real urgent/authority paths and existing questions/cards/approvals remain available. Existing task mute/budgets are not widened; muted watcher reports retain the outbox/card route.
- Final/interim model narration is internal. It never increments sent or satisfies reply-debt. The existing once-per-batch reply nudge directs the agent to send_message, not an internalized message block. An explicit internal 'no reply' remains possible for acknowledgments that warrant silence. Suppressed task and interim message blocks are durable work_log records. A task that attempts an explicit message receives one tool-directed recovery nudge only when its budget permits and no notification was already queued. Plain background narration never causes a recovery turn. Missing replies are archived as undelivered rather than falsely completed.
- Routine outcome payload requires short product result, verified result, accessible evidence URL and optional material remaining/needs-you fields. Target about 60 words; oversized output is rejected, never silently truncated. Canonical work identity comes from a normalized GitHub PR/issue or original Slack human-request permalink, not an invented phase/review-round key. Semantic completion and correct initiating identity remain agent judgments, not certified by the schema.
- Host destination authorization remains first. One atomic unique central receipt claim then serializes actual workgroup + canonical item across siblings/sessions. The tool queues, reads existing inbound delivery acknowledgment, and distinguishes confirmed receipt, failure and unconfirmed. Existing delivered tables are PER-SESSION inbound tables: src/db/schema.ts begins INBOUND_SCHEMA at175; src/mailbox/sqlite/index.ts opens/migrates the session inboundPath. They cannot provide work-item dedupe.
- A successful adapter return is acknowledged even if it supplies no platform ID. A thrown send with unknown platform acceptance is held, never blindly re-posted. The operator reconcile tool requires current updated_at plus an evidence reason; it can confirm existing delivery, permit the original queued row after verified non-delivery, or correct a confirmed mistaken identity. Operator must drain/reconcile queued copies before rekeying. Receipt history is retained; no normal caller revision escape hatch exists. Material later corrections use existing edits or urgent updates.
- Typed routine outcomes bypass daily task/turn/key auto-anchors. Ordinary original human threads remain; a scheduled outcome tied to an original Slack request can use that exact thread. Unrelated completed work gets independent reports, not one giant daily thread.
- A deployment can reserve a physical channel for an existing terminal reporter through outcomeReportingExternalChannels. Native typed outcomes to that channel are refused, while human replies, approvals and urgent corrections retain their existing routes. The external reporter and its receipts are outside this source contribution; no cross-route or universal exactly-once guarantee is made.
