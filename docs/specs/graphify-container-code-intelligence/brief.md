# Brief: Graphify Container Code Intelligence

> Generated by `/team-brief` — 2026-07-18
> Saved to: `docs/specs/graphify-container-code-intelligence/brief.md`

## Requirements

- Retire GitNexus completely from NanoClaw container agents: no GitNexus CLI, MCP server, runtime injection, generated instructions, container plugin activation, readiness hook, commit advisory, or GitNexus-specific container skills remain active or installed in the agent image.
- Keep host/operator development tooling outside container agents out of scope; removing GitNexus from container agents must not require removing an operator's host-side GitNexus installation.
- Install a pinned Graphify CLI in the agent container image and make it available consistently to every supported container-agent provider.
- Keep code work lazy: knowledge-only Slack, Discord, and other channel threads must not create worktrees or build indexes merely because a container starts.
- Continue using the managed `create_worktree` lifecycle when a thread first needs repository work so the repository is fetched and a thread worktree is created or safely refreshed before code intelligence is used.
- Store each generated Graphify index as thread-scoped, per-repository cache data outside the checked-out repository so indexing never dirties `git status` or creates commit candidates.
- Enforce index freshness automatically before every Graphify graph query. A missing index must be built; an existing index must be incrementally reconciled with the current worktree before the query runs.
- Freshness must cover committed changes, rebases, modified tracked files, new untracked source files, and deleted files. It must not depend solely on commit hooks or `HEAD` comparison.
- Never require a user or operator to remember or manually request an index refresh.
- Fail closed on freshness: if the refresh cannot complete, the agent must not silently query a known-stale graph. It may report the failure and continue using authoritative source inspection without Graphify.
- Serialize refresh/query activity per thread and repository so sibling agents sharing a thread cannot corrupt or race the same index.
- Run Graphify as one-shot CLI processes that exit after extraction or query; do not add a persistent Graphify MCP server or daemon to container sessions.
- Ensure generated indexes are disposable and are removed with the owning thread/session workspace lifecycle.
- Provide agent-facing instructions or a skill that makes the automatic freshness and Graphify CLI workflow the default code-intelligence workflow without relying on model memory.
- Validate the replacement with automated tests plus production-style container/worktree exercises, including initial indexing, unchanged re-query, dirty-file refresh, added/deleted-file refresh, concurrent access, refresh failure, container restart, and cleanup.

## Constraints

- [HARD] Container-agent operation must be fully agentic; index correctness cannot require manual refresh commands or operator intervention.
- [HARD] GitNexus must be absent from the container-agent runtime after activation, not merely disabled in prompts.
- [HARD] Graphify must remain CLI-only and must not hold idle memory between requests.
- [HARD] Generated graph data must remain outside source repositories and Git history.
- [HARD] The existing managed-worktree safety rules remain authoritative, including dirty-worktree and explicit-branch behavior.
- [HARD] The same behavior must apply across supported Claude, Codex, and other provider-backed container agents.
- [HARD] Dependency installation must preserve the repository's pinned-version and supply-chain policies; no release-age or build-script bypass may be added without explicit approval.
- [HARD] A failed or interrupted refresh must not replace a previously valid index with a partially written index.
- [SOFT] Avoid paying Graphify's transient extraction cost until a thread actually asks for graph-backed code intelligence.
- [SOFT] Reuse a valid thread-scoped index across container restarts rather than rebuilding it unnecessarily.

## Non-Goals (Explicitly Out of Scope)

- Removing GitNexus from the operator host or from this repository's contributor-development requirements.
- Committing generated Graphify indexes into application repositories.
- Running a persistent Graphify MCP server, watcher, or background daemon.
- Automatically creating a worktree for every messaging thread before code work is requested.
- Treating Graphify output as more authoritative than the checked-out source, Git state, tests, or build results.
- Live service restart while unrelated container turns are in flight without an explicit safe rollout decision.

## Key Concepts

- **Source freshness:** The managed worktree's relationship to `origin/HEAD`, established by `create_worktree` without overwriting dirty or deliberately selected branches.
- **Index freshness:** The generated graph reflects the current worktree contents, including uncommitted changes, at the moment a graph query begins.
- **Query-time freshness gate:** The mandatory incremental extraction/reconciliation that completes successfully before a Graphify query may execute.
- **Thread-scoped index:** Disposable generated graph data owned by one messaging thread/session and repository, isolated from other threads and stored outside Git.
- **One-shot CLI:** A process invoked for a bounded extraction or query operation that exits afterward and retains no idle runtime memory.

## Open Questions

- **Live activation:** Defaulting to building and validating the replacement image while holding disruptive service/container restarts until current in-flight turns are checked and the rollout is explicitly safe.

## Success Criteria

- A repository-wide search and built-image inspection show no active GitNexus binary, MCP configuration, plugin activation, hooks, skills, or agent instructions inside container agents.
- The built container exposes the pinned Graphify CLI on every provider path without downloading it at query time.
- A fresh managed worktree can build an index and complete a Graphify query with no manual preparation.
- Repeating the query on an unchanged worktree uses the incremental/no-change path and returns current results.
- Editing, adding, and deleting source files changes the next query's graph results without a commit or manual refresh.
- A forced extraction failure prevents a stale query and leaves the last complete index usable for later recovery.
- Concurrent sibling attempts are serialized and do not corrupt the graph cache.
- Restarting the container preserves and revalidates the thread-scoped index; cleaning the thread workspace removes it.
- Host build, host tests, container typecheck/tests, image build, and production-style runtime checks pass with documented outputs.
